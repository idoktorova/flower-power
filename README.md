# Flower Power

## Запуск через Docker Compose

Приложение должно знать публичный адрес, доступный телефону. Перед запуском задайте
`PUBLIC_URL` — внешний URL приложения. Можно указать домен или IP-адрес; если
протокол не указан, приложение автоматически добавит `http://`:

```bash
PUBLIC_URL=https://plants.example.com/ docker compose up --build -d
```

Например, для локальной сети допустима короткая запись `PUBLIC_URL=192.168.1.50:4173`.

Этот адрес попадёт в QR-коды. `localhost` в QR-коде использовать нельзя: на телефоне
он обозначает сам телефон, а не сервер.

Если внешний порт отличается от `4173`, его можно настроить отдельно:

```bash
PUBLIC_URL=http://192.168.1.50:8080/ FLOWER_POWER_PORT=8080 docker compose up --build -d
```

Для использования через интернет рекомендуется домен с HTTPS и reverse proxy
(например, Nginx или Caddy), который перенаправляет запросы на порт контейнера `4173`.

Типы растений, карточки и история ухода хранятся в SQLite-базе внутри Docker volume
`flower-power-data`. Загруженные изображения остаются в отдельном volume
`flower-power-uploads`, а ссылки на них сохраняются вместе с карточками в базе.

После двух и более отметок о поливе приложение определяет обычный интервал по
последним записям. Когда этот интервал проходит, напоминание появляется в списке
растений и в самой карточке; новая отметка о поливе автоматически его скрывает.

В карточке растения история показана календарём от даты покупки до сегодняшнего
дня. Капля обозначает полив, звёздочка — внесение удобрения. Если навести курсор
на отмеченный день или сфокусировать его средствами доступности, можно увидеть
всплывающую карточку с температурой, влажностью, временем полива и названием
использованного удобрения. Климатические значения отображаются, если у события
есть поля `temperature`/`temp` и `humidity` либо в растении сохранён массив
`climateReadings` с такими показаниями и датой.

## Температура и влажность: рекомендуемые интеграции

Для улицы оптимален [Open-Meteo](https://open-meteo.com/en/docs): приложение может
получить координаты через браузерный Geolocation API и запросить текущие поля
`temperature_2m` и `relative_humidity_2m`. API не требует ключа для некоммерческого
использования, поэтому его удобно подключить первым. Геолокацию нужно запрашивать
только по явному действию пользователя; в опубликованной версии для неё нужен HTTPS.

Данные Xiaomi внутри помещения лучше получать не из облака Xiaomi напрямую, а через
[интеграцию Xiaomi BLE в Home Assistant](https://www.home-assistant.io/integrations/xiaomi_ble/).
Home Assistant принимает BLE-показания метеостанции локально и отдаёт нормализованные
сенсоры температуры и влажности через свой
[REST API](https://developers.home-assistant.io/docs/api/rest/). Для этого рядом с
датчиком нужен Bluetooth-адаптер или Bluetooth proxy на ESPHome. Точная схема зависит
от модели метеостанции: некоторым зашифрованным датчикам Xiaomi требуется bind key.

Рекомендуемый следующий этап — добавить на сервер Flower Power два адаптера:

1. `OpenMeteoProvider` для наружных показаний по широте и долготе;
2. `HomeAssistantProvider` для сущностей вида `sensor.*_temperature` и
   `sensor.*_humidity`, причём URL и long-lived access token хранить только в
   переменных окружения сервера, а не в браузере.

Так карточка сможет показывать рядом два независимых источника — «на улице» и
«в комнате» — и сопоставлять фактический микроклимат с требованиями растения.

Если `PUBLIC_URL` не задан, приложение использует адрес, по которому открыт кабинет
в браузере. Это удобно только когда кабинет уже открыт через публичный домен.

## Печать QR на термоэтикетках AIYIN

Установите системный драйвер принтера AIYIN. В карточке растения нажмите на QR-код,
а затем **«Печатать»**. Приложение передаёт в системный диалог только обрезанный
квадрат QR-кода размером **21 × 21 мм** и разрешением **203 dpi** (**168 × 168 точек**)
— без макета этикетки, текста и дополнительных полей. QR остаётся векторным и
растрируется драйвером в разрешении термопринтера. Размер физической этикетки
(например, **45 × 25 мм**) задаётся в драйвере принтера.

## GitHub Pages

Workflow `.github/workflows/pages.yml` автоматически публикует статическую версию.
В настройках репозитория выберите **Settings → Pages → Source → GitHub Actions** и
запустите workflow **Deploy to GitHub Pages**. Относительные пути позволяют работать
по адресу вида `https://user.github.io/flower-power/` без дополнительной настройки.

QR-код содержит не только ссылку GitHub Pages, но и основные сведения о растении,
поэтому карточка откроется на телефоне, где ещё нет данных в `localStorage`.

GitHub Pages не выполняет Node.js-код. Поэтому фотография, сделанная в Pages-версии,
сохраняется только в браузере текущего устройства. Для серверного хранения фотографий
нужно использовать Docker-вариант приложения.

## Импорт и экспорт типов растений

Кнопка **JSON** рядом с заголовком «Типы растений» открывает дополнительный редактор.
Он экспортирует текущие типы и принимает объект с массивом `types`, массив типов или
один тип. У типа обязательным является поле `name`; инструкции задаются в `care`, а
пары «насекомое — средство борьбы» — в массиве `pests`:

```json
{
  "name": "Фикус",
  "care": {
    "lighting": "Яркий рассеянный свет",
    "fertilizer": "Удобрение для фикусов, 5 мл на 1 л воды"
  },
  "pests": [
    { "insect": "Паутинный клещ", "treatment": "Акарицид по инструкции" }
  ]
}
```
