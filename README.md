# Flower Power

## Запуск через Docker Compose

Приложение должно знать публичный адрес, доступный телефону. Перед запуском задайте
`PUBLIC_URL` — полный внешний URL приложения с протоколом (`https://`):

```bash
PUBLIC_URL=https://plants.example.com/ docker compose up --build -d
```

Этот адрес попадёт в QR-коды. `localhost` в QR-коде использовать нельзя: на телефоне
он обозначает сам телефон, а не сервер.

Если внешний порт отличается от `4173`, его можно настроить отдельно:

```bash
PUBLIC_URL=http://192.168.1.50:8080/ FLOWER_POWER_PORT=8080 docker compose up --build -d
```

Для использования через интернет рекомендуется домен с HTTPS и reverse proxy
(например, Nginx или Caddy), который перенаправляет запросы на порт контейнера `4173`.

Если `PUBLIC_URL` не задан, приложение использует адрес, по которому открыт кабинет
в браузере. Это удобно только когда кабинет уже открыт через публичный домен.

## GitHub Pages

Workflow `.github/workflows/pages.yml` автоматически публикует статическую версию.
В настройках репозитория выберите **Settings → Pages → Source → GitHub Actions** и
запустите workflow **Deploy to GitHub Pages**. Относительные пути позволяют работать
по адресу вида `https://user.github.io/flower-power/` без дополнительной настройки.

QR-код содержит не только ссылку GitHub Pages, но и основные сведения о растении,
поэтому карточка откроется на телефоне, где ещё нет данных в `localStorage`.

GitHub Pages не выполняет Node.js-код. Поэтому фотография, сделанная в Pages-версии,
сохраняется только в браузере текущего устройства. Для серверного хранения фотографий
нужно использовать Docker-вариант приложения.
